# UI ACCEPTANCE CRITERIA — Design, UX, Commerce, Performance

استخدم هذه القائمة مع [QUALITY_AND_RELEASE.md](QUALITY_AND_RELEASE.md) و[COMMERCE_CONTRACT.md](COMMERCE_CONTRACT.md). المربعات غير المؤشرة متطلبات مستقبلية وليست فحوصًا منفذة. لا يحقق النموذج البصري وحده اختبارات التجارة.

## 1. المراجعة البصرية
- [ ] الاتجاه البصري متوافق مع `ART_DIRECTION.md`.
- [ ] استخدام tokens موحد؛ لا توجد ألوان ومسافات عشوائية.
- [ ] الصور حقيقية ومناسبة للمنتج، ولا تشوّه العبوة.
- [ ] التسلسل البصري واضح: العنوان، المعلومة، الإجراء الأساسي.
- [ ] لا توجد عناصر متداخلة أو نصوص مقطوعة أو مساحات فارغة غير مقصودة.
- [ ] لا توجد تأثيرات أو زخارف تضعف وضوح المنتج.
- [ ] حالات التحميل والخطأ والفراغ ونفاد المخزون مصممة.

## 2. الشاشات والتجاوب
اختبر على الأقل:
- [ ] هاتف بعرض 320–375px.
- [ ] هاتف بعرض 390–430px.
- [ ] جهاز لوحي أو عرض متوسط.
- [ ] Desktop بعرض 1280px أو أكثر.
- [ ] RTL بالعربية، مع اختبار النصوص الطويلة.
- [ ] لا يوجد تمرير أفقي غير مقصود.
- [ ] الأزرار والحقول لا تتداخل مع لوحة مفاتيح الهاتف.
- [ ] لا يعتمد أي إجراء أساسي على hover.
- [ ] التنقل والقوائم والحوارات قابلة للاستخدام باللمس.

## 3. الحركة
- [ ] الحركة تخدم معنى أو تسلسلًا بصريًا.
- [ ] لا تمنع الحركة التمرير الطبيعي.
- [ ] لا يوجد صوت تلقائي.
- [ ] يمكن الوصول إلى المنتجات دون مشاهدة مقدمة طويلة.
- [ ] `prefers-reduced-motion` محترم.
- [ ] لا توجد حركة تسبب اهتزازًا أو قفزًا في التخطيط.
- [ ] تم اختبار الأداء على جهاز متوسط أو محاكاة مناسبة.

## 4. الصفحة الرئيسية
- [ ] يظهر المنتج الأساسي بسرعة.
- [ ] الشعار والرسالة وCTA واضحة.
- [ ] يمكن الانتقال إلى المنتجات بسهولة.
- [ ] توجد روابط واضحة للمجموعات والمنتجات.
- [ ] أي ادعاءات تسويقية موثقة.
- [ ] المحتوى الأساسي مفهوم حتى إذا لم تعمل المؤثرات.

## 5. قائمة المنتجات
- [ ] البحث والفرز والفلاتر تعمل فعليًا.
- [ ] حالة عدم وجود نتائج مفهومة.
- [ ] السعر والتوفر صحيحان.
- [ ] بطاقات المنتجات متسقة.
- [ ] لا توجد نتائج أو تقييمات مختلقة.
- [ ] الفلاتر قابلة للاستخدام على الهاتف.

## 6. صفحة المنتج
- [ ] الصور قابلة للمشاهدة والتبديل، والتكبير إن تقرر.
- [ ] الاسم والسعر والحجم والتوفر واضحون.
- [ ] المكونات والنفحات لا تعرض إلا إذا كانت بيانات موثقة.
- [ ] اختيار الحجم/النسخة يغير السعر والمخزون بصورة صحيحة.
- [ ] زر الإضافة للسلة يوضح النجاح أو الخطأ.
- [ ] منع إضافة كمية أكبر من المتاح.
- [ ] بيانات المنتج المهمة موجودة في HTML/metadata المناسبة للفهرسة.

## 7. السلة والدفع
- [ ] يمكن تغيير الكمية والحذف.
- [ ] يعاد احتساب الأسعار على الخادم.
- [ ] تظهر تكلفة الشحن والخصومات بوضوح وفق السياسة المعتمدة.
- [ ] رسائل التحقق مفهومة ولا تمسح المدخلات بلا داعٍ.
- [ ] لا يمكن تكرار إنشاء الطلب بسبب double-click أو إعادة إرسال الطلب؛ التحقق على الخادم بمفتاح تكرار، وليس تعطيل الزر فقط.
- [ ] تغير السعر/الشحن وانتهاء quote ونفاد المخزون يعرض تعارضًا واضحًا قبل الدفع.
- [ ] اختبار آخر قطعة متزامن، مع عدم تسرب الحجوزات أو تكرار تحريرها.
- [ ] السلة ورابط الطلب محميان بملكية أو تصريح وصول؛ لا كشف بتغيير المعرف.
- [ ] إذا اعتمدت الباقة، يحجز مخزون جميع المكونات وتعرض محتوياتها الحقيقية.
- [ ] تأكيد الدفع يعتمد على تحقق الخادم، لا رسالة المتصفح فقط.
- [ ] بيانات الدفع الحساسة لا تُسجّل في logs.
- [ ] حالات فشل الدفع والإلغاء والنجاح والدفع المعلق واضحة؛ COD لا يعرض paid قبل التحصيل.
- [ ] أحداث الدفع المكررة والمتأخرة ومعكوسة الترتيب لا تكرر الأثر ولا تؤكد طلبًا بلا مخزون.

## 8. الوصول والجودة
- [ ] التنقل بلوحة المفاتيح ممكن.
- [ ] focus-visible واضح.
- [ ] labels مرتبطة بالحقول.
- [ ] alt للصور المفيدة وalt فارغ للزخرفية.
- [ ] رسائل الخطأ لا تعتمد على اللون فقط.
- [ ] لا توجد أخطاء JavaScript حرجة في console.
- [ ] لا توجد أخطاء شبكة غير معالجة في المسارات الأساسية.

## 9. الأداء وSEO
- [ ] الصور محسنة وتستخدم أحجامًا مناسبة.
- [ ] لا يتم تحميل مكتبات 3D في كل الصفحات بلا داعٍ.
- [ ] أبعاد الصور/الحاويات تمنع layout shift.
- [ ] metadata وعناوين الصفحات فريدة ومناسبة.
- [ ] canonical وsitemap وrobots مضبوطة عند الحاجة.
- [ ] structured data تعكس بيانات المنتج الحقيقية فقط.
- [ ] قبل الإطلاق: نتائج lab محفوظة مع الجهاز والشبكة والإصدار، وفحص LCP/CLS والتفاعلات وفق QUALITY_AND_RELEASE.
- [ ] بعد الإطلاق: تجمع Core Web Vitals الميدانية عند توفر زيارات كافية؛ غياب البيانات لا يسجل نجاحًا أو يتحول إلى عائق مستحيل قبل الزوار.
- [ ] الأهداف المرجعية: LCP ≤ 2.5s، INP ≤ 200ms، CLS ≤ 0.1 عند المئين 75 من بيانات المستخدمين الفعلية.

## 10. بوابة القبول
لا تُقبل الصفحة إذا كان فيها:
- خطأ يمنع الشراء أو يعرض سعرًا غير صحيح.
- مشكلة أمان حرجة.
- كسر واضح على الهاتف.
- CTA غير قابل للاستخدام.
- صورة منتج مضللة أو مشوهة.
- اختبار تجارة حرج فاشل أو غير منفذ؛ تفسير التعذر وخطة الإصلاح لا يعنيان اجتياز البوابة.

## 11. المحتوى والخصوصية والتشغيل

- [ ] اسم ORQ وشعاره وعبارته مطابقون للاعتماد، وBlack Gold لا يظهر كاسم متجر بديل.
- [ ] لا أسعار من عمود الاقتراح ولا أحجام مستنتجة من الصور؛ كل SKU منشور معتمد.
- [ ] لا إعلان باقة أو سعر مدمج يخالف العرض الحالي.
- [ ] لا طلبات/سلال/صفحات إدارة في cache عام أو sitemap.
- [ ] لا معلومات شخصية أو رموز وصول ضمن analytics أو لقطات الأدلة.
- [ ] يمكن للإدارة تنفيذ الطلب وتصحيح المخزون بصلاحية وسجل سبب، دون تعديل قاعدة البيانات يدويًا.
- [ ] وضعت نتيجة الفحص ورابط الدليل والمقاس والبيئة في تقرير المرحلة.
