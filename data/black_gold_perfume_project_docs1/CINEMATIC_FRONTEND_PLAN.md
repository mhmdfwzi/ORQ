# CINEMATIC FRONTEND PLAN - ORQ / Gemini

التاريخ: 2026-10-28. المنفذ المستهدف: **Gemini**. الحالة: خطة ومواصفة؛ لم ينفذ كود الواجهة بعد.

## 1. المهمة والنتيجة المطلوبة

نفذ واجهة Next.js لعطور ORQ الرجالية تستعير تكوين الإعلان السينمائي: زجاج واضح، حجر داكن، إضاءة ذهبية جانبية، مساحات واسعة، وحركة محدودة تصنع العمق. يجب أن تكون كل لقطة قوية وهي ثابتة، ثم تتحسن بالحركة.

المخرج الأول **نموذج محلي قابل للتصفح** للرئيسية وصفحة منتج، ثم اعتماد الاتجاه قبل تعميمه. بعد الاعتماد تكتمل القائمة واستكشاف النفحات والسلة ومعاينة checkout. هذه المهمة تخص الواجهة؛ Laravel وعقود التجارة تظل كما في خطة المشروع.

المراجع الملزمة: [PROJECT_BRAIN](PROJECT_BRAIN.md)، [ART_DIRECTION](ART_DIRECTION.md)، [DESIGN_SYSTEM](DESIGN_SYSTEM.md)، [MVP_SCOPE](MVP_SCOPE.md)، [UNIVERSAL_WORKRULES](UNIVERSAL_WORKRULES.md). البرومبت الجاهز للبدء في [GEMINI_FRONTEND_PROMPT](GEMINI_FRONTEND_PROMPT.md).

## 2. ما يستطيع جيميني البدء به الآن

- افحص المجلد أولًا؛ وقت كتابة الخطة لا يوجد تطبيق أو Git أو package.json. إذا أضيف كود لاحقًا، استخدم الموجود بدل إعادة التأسيس.
- يمكن بدء نموذج Phase 1 بالتوازي مع قرارات Phase 0 التجارية: الألوان والتخطيط والحركة والمكونات لا تحتاج بوابة دفع أو قائمة أسعار نهائية.
- إذا لم يوجد Next.js، أنشئ داخل frontend/ الحد الأدنى اللازم للمعاينة: App Router وTypeScript وملف قفل حزم وإعداد تحقق وتعليمات تشغيل. افحص توافق الأدوات قبل اختيار الإصدارات. لا تنشئ Laravel أو خدمات أو مستودع remote لهذه المهمة.
- مسارات المعاينة تبدأ بـ /preview؛ كل البيانات فيها تطويرية موسومة. لا نشر عام ولا تحصيل ولا إنشاء طلب حقيقي.
- لا تحول إنشاء تطبيق المعاينة إلى إعلان اكتمال Phase 2؛ تأسيس التطبيقين وعقد API والربط لهما بوابة منفصلة.
- القرارات D01/D03/D09 تؤثر على النسخة النهائية. سجل النقص، واستمر بمرجع ORQ الحالي ونصوص مسودة وصور موسومة أو مواضع صور عند الحاجة.

7. تحقق من حدة المصادر ذات عرض 1024px؛ لا تكبرها قسرًا لملء شاشة 4K. استخدم إطارًا فنيًا ومساحة داكنة حولها إن لزم.

## 5. خريطة المشاهد

### S0 - إطار الموقع والتنقل

- Header هادئ بارتفاع مبدئي 72px للواسع و64px للهاتف، شعار/كتابة ORQ، روابط للأجزاء الموجودة، وزر قائمة للهاتف وسلة عند تنفيذها.
- في النموذج المحلي عند عدم وجود ملف شعار مناسب، استخدم كتابة ORQ مؤقتة واضحة؛ لا تعِد تصميم الشعار أو تستخرج شعارًا مشوهًا من إعلان.
- يمكن sticky بتعتيم مقروء أثناء التمرير؛ لا يتغير ارتفاعه ولا يدفع الصفحة. لا تستخدم blur مكلفًا عبر مساحة الشاشة كلها.
- القائمة dialog بلوحة مفاتيح وEscape وإعادة focus. أهداف اللمس 44×44px على الأقل.
- لا يظهر رابط لحساب أو اختبار عطر أو صفحة لم تنفذ. CTA الافتتاحية تصل إلى قسم المجموعة الحقيقي ذي id="signature"؛ روابط التنقل من PDP تعود إلى /preview#signature بدل anchor في صفحة أخرى.

### S1 - The Arrival / المشهد الافتتاحي

**الهدف:** التعرف على ORQ والمنتج وإمكانية الاستكشاف في أول شاشة.

- الواسع: تكوين غير متماثل، مساحة صورة نحو 58% يسارًا ونص عربي نحو 42% يمينًا. النص لا يتداخل مع العبوات؛ خلفه سطح هادئ.
- الهاتف: عنوان ووصف وCTA في تدفق طبيعي، ثم تركيب صورة واضح؛ لا تفرض ارتفاع شاشة كاملًا إذا أخفى المنتج أو الزر.
- ارتفاع الواسع نقطة بداية min-height: calc(100svh - ارتفاع Header)، مع fallback مناسب ودون height ثابت يقص المحتوى.
- طبقات المشهد من الخلف للأمام: خلفية داكنة، هالة ذهبية محلية، الصورة، ثم veil زخرفي خفيف بعيد عن النص. جميع الزخارف pointer-events: none وaria-hidden.
- العنوان والمنتج وCTA ظاهرة في HTML/CSS الأساسي من أول عرض، ولا تبدأ opacity: 0. النسخة الثابتة هي النتيجة الافتراضية عند فشل JavaScript.
- ضوء واحد يمر برفق مرة واحدة بعد تهيئة الصورة؛ لا شاشة تحميل ولا عد تنازلي ولا شرط انتظار للتمرير.
- عند التمرير الطبيعي يمكن إزاحة الصورة كلها بحد أقصى 18px على الواسع؛ لا pin ولا دوران زجاجة ولا تقريب يصغر/يكبر النص.

**القبول:** الوصول للمجموعة فورًا، ظهور العبوة كاملة، وعدم تكرار العبارة المدمجة في الصورة خلف عنوان HTML.

### S2 - Signature Collection / المجموعة

- عنوان «اكتشف المجموعة»، وصف قصير، ورابط للقائمة عند تنفيذها. كلمة «الأكثر مبيعًا» لا تستخدم دون بيانات.
- في نموذج أول اتجاه: منتج تجريبي واحد يقود إلى PDP. بعد اعتماد الاتجاه: 3-4 منتجات كحد أقصى في الرئيسية، والقائمة تستوعب الباقي.
- للواسع: منتج بارز بتكوين أوسع وبقية المنتجات بإيقاع متوازن؛ بطاقات الصورة بلا حدود ذهبية متكررة. لكل بطاقة اسم وصورة وحجم/سعر عندما يكونان معتمدين.
- للهاتف: عمود واحد على 320px؛ يمكن عمودان من 390px إذا ظلت العبوة والاسم والسعر مقروءة. لا carousel إجباري يخفي المنتجات.
- hover اختياري للصورة ≤ 1.025 scale، مع نفس الإجراء متاح باللمس وfocus. لا تنزلق معلومات السعر خارج البطاقة.
- رابط البطاقة يفتح المنتج؛ زر الإضافة مستقل وليس button داخل link.

### S3 - Explore the Notes / داخل التكوين

- قسم قصة لرائحة المنتج المختار، وليس اختبار توصية أو ميزة جديدة خارج MVP.
- الواسع: صورة/تفصيلة زجاج في عمود، ونفحات في عمود آخر. ثلاث مجموعات «الافتتاحية / القلب / القاعدة» من بيانات المنتج المراجعة فقط.
- على الهاتف تظهر المجموعات تباعًا دون تمكين hover أو تمرير أفقي لفهمها.
- تفاعل اختياري بسيط بأزرار/تبويبات: يحدد مجموعة نفحات ويغير الوصف أو الإبراز؛ اختيار لوحة المفاتيح والتسمية واضحان. المعلومات الأساسية تظل قابلة للقراءة دون مؤثرات.
- لا تستخدم صور حمضيات أو عود لتأكيد مكون غير موثق. عند نقص البيانات، يحذف القسم في الإنتاج ويعرض موضعه الموسوم في المعاينة فقط.

### S4 - The Detail / التفاصيل والحرفة

- تكوين أهدأ من Hero: صورة تفاصيل على حجر داكن، نص قصير، ورابط للمجموعة/المنتج.
- لا تختلق تاريخ علامة أو بلد تصنيع أو صناعة يدوية أو شهادات أو أرقام عملاء. يمكن استخدام عبارة تحريرية مثل «تفاصيل تصنع حضورًا» كمسودة.
- بلا parallax إضافي؛ التباين بين السكون والحركة جزء من إيقاع الصفحة.
- قصة البراند النهائية تحتاج محتوى D09؛ about.md الحالي فارغ.

### S5 - الثقة والختام

- روابط الشحن والإرجاع والتواصل والخصوصية؛ لا تكتب «شحن مجاني» أو «استرجاع خلال X يومًا» أو وعود دفع دون اعتماد.
- قسم الهدايا/الباقة اختياري فقط بعد D07. لا تستعمل صور 750 جنيه كعرض مفعل تلقائيًا.
- Footer بسيط ومقروء، بلا newsletter أو روابط اجتماعية صورية أو شعارات وسائل دفع غير مفعلة.

## 6. صفحة المنتج وبقية رحلة المعاينة

**PDP:** صورتها/معرضها بنحو 55% من مساحة الواسع، ومعلومات النسخة والشراء 45%؛ على الهاتف معرض ثم اسم وسعر وحجم وتوفر وCTA، ثم الوصف والنفحات والشحن. ترتيب DOM يظل منطقيًا لقارئ الشاشة.

- السعر والحجم والتوفر ثابتة أثناء الحركة. لا ضباب فوق Gallery أو زر الإضافة، ولا حركة دخول على حقول اختيار النسخة.
- معرض الصور يبدل الصور بأزرار مسماة، ويحجز نسبة الصورة لمنع قفز الصفحة. لا حاجة لتكبير معقد في التسليم الأول.
- زر شراء ثابت على الهاتف اختياري بعد اختبار safe area ولوحة المفاتيح؛ لا يكرر التركيز أو يغطي أخطاء الحقول.
- مسارات النموذج: /preview، /preview/collection، /preview/products/[slug]، /preview/cart، /preview/checkout. ينشئ كل مسار عند الوصول لمهمته، ولا تعرض روابط له قبل ذلك.
- القائمة: بحث وفرز وفلاتر بسيطة وحالات عدم وجود نتائج؛ استخدام URL لحالة الفلاتر عند تنفيذها.
- السلة: drawer أو صفحة، إضافة/تعديل/حذف ورسالة مقروءة؛ كل الإجراءات محاكاة محلية معلنة ما دام لا يوجد API.
- checkout: نموذج بصري بحالات الحقول والخطأ والتحميل فقط؛ لا إدخال بيانات دفع حساسة ولا اتصال مزود. نهاية التجربة تقول «انتهت المعاينة؛ لم يتم إنشاء طلب».
- الأسعار المجهولة null، والمخزون المجهول unknown، وليسا صفرًا أو نفادًا. إن لزم سيناريو حساب، استخدم fixture اختبار منفصلًا مسمى بوضوح ولا تنسب سعره إلى منتج ORQ حقيقي.
- إذا لم تتوفر بيانات شراء، الإجراء العام «عرض التفاصيل». أي «إضافة تجريبية» تعلن أنها محاكاة، ولا يظهر «تم الدفع».

## 7. مواصفة الحركة

الأرقام التالية حدود بداية؛ تقليلها جائز لتحسين القراءة والأداء. لا تجمع أكثر من حركة زخرفية مستمرة في نفس الشاشة. التنفيذ الافتراضي بلا أي حلقة مستمرة.

| ID | العنصر / المشغل | الواسع مع حركة عادية | الهاتف | reduced-motion / غياب JS |
| --- | --- | --- | --- | --- |
| M01 | ضوء Hero بعد تهيئة الصورة | انتقال هالة محلية 1000-1400ms، مرة واحدة؛ العنوان ثابت | هالة ثابتة أو انتقال opacity خفيف ≤ 600ms | صورة وهالة ثابتتان |
| M02 | عمق Hero أثناء التمرير | translateY حتى 18px للصورة، داخل حاوية تمنع حواف فارغة؛ لا يؤخر التنقل | معطل | معطل |
| M03 | دخول زخرفة/تفصيلة أسفل الطية | 8-12px إلى موضعها، 400-600ms، مرة واحدة | 4-8px أو سكون | موضع نهائي ظاهر |
| M04 | صورة منتج عند hover/focus | scale حتى 1.025 خلال 180-220ms، دون تحريك النص | حالة ضغط بسيطة؛ لا يعتمد المحتوى على hover | تغير حد/لون دون إزاحة |
| M05 | زر / feedback | تغير لون/حد 150-200ms؛ النص والحجم ثابتان | نفس السلوك | تغير مباشر |
| M06 | سلة أو قائمة modal | opacity وtranslateX حتى 24px خلال 180-240ms؛ اتجاه يناسب RTL | نفس المدة أو أقصر | فتح مباشر مع إدارة focus |
| M07 | تغيير صورة/تبويب نفحات | crossfade ≤ 180ms دون تغيير أبعاد الحاوية | نفس السلوك | تبديل مباشر |

قواعد التنفيذ:

- ابدأ بـCSS للضوء وhover والحوارات، وIntersectionObserver لتحسينات دخول محدودة عند الحاجة. لا حاجة لمكتبة لكل مشهد.
- إذا احتاج M02 أو التسلسل إلى GSAP، استخدمه وحده لهذا الجزء مع ScrollTrigger عند الحاجة؛ لا تضف مكتبة ثانية للغرض نفسه.
- ضع تهيئة الحركة داخل مكون عميل محدود بالمشهد، وحدد عناصره عبر refs. نظف listeners وobservers وtweens وScrollTriggers عند unmount وتغير breakpoint.
- افصل إتاحة الحركة عن العرض المرئي الأساسي؛ لا تخفِ النصوص أو المنتج قبل نجاح imports. لا تعد الصورة إلى opacity: 0 عند التنقل.
- راقب prefers-reduced-motion وتغيره أثناء فتح الصفحة، وقيد hover/pointer بوسائط مناسبة. لا تجعل touch جهازًا يعتمد على mousemove.
- لا تستخدم setState مع كل scroll tick؛ إن لزم handler يحدّث transform عبر requestAnimationFrame، وينظف عند المغادرة.
- حرك transform/opacity في مساحات محدودة؛ لا animation لـwidth/height/top/left أو blur ضخم أو ظل كثيف يغطي الشاشة. لا تضع will-change دائمًا على كل البطاقات.
- لا تفصل حروف النص العربي لإنشاء stagger يقطع اتصالها. حرك كتلة أو سطرًا كاملًا مع بقاء النص الدلالي سليمًا.
- Three.js/WebGL ومقدمة فيديو والصوت وscroll-jacking وpin طويل خارج هذه الخطة. الإحساس السينمائي هنا من التكوين والضوء والعمق المحدود.

## 8. هيكل التنفيذ المقترح

يتكيف مع أي كود موجود؛ لا تنشئ ملفات فارغة لكل اسم. أسماء المجلدات أدناه نسبية إلى frontend/:

```text
src/app/layout.tsx                         # lang=ar وdir=rtl وخطوط أساسية
src/app/preview/page.tsx                   # تجميع مشاهد الرئيسية
src/app/preview/collection/page.tsx
src/app/preview/products/[slug]/page.tsx
src/app/preview/cart/page.tsx
src/app/preview/checkout/page.tsx
src/components/layout/                    # Header وFooter وMobileMenu
src/components/cinematic/                 # HeroScene وNotesSection وDetailSection
src/components/catalog/                   # ProductCard وProductGallery وProductInfo
src/components/cart/                      # التفاعل المحلي عند الوصول إلى المهمة
src/components/ui/                        # Button وDialog وFormField حسب الحاجة
src/lib/catalog/                          # أنواع بيانات العرض ومصدرها
src/data/preview/                         # fixtures + media manifest؛ ليست بيانات بيع
src/styles/tokens.css
src/styles/motion.css
public/media/orq/                         # نسخ العرض؛ الأصول تبقى في photo/
README.md                                 # الإعداد والتشغيل والتحقق وحدود النموذج
```

- صفحات وتجميع المحتوى ثابتة أو Server Components؛ client فقط للحركة والقائمة والمعرض والسلة. لا تحول layout أو الصفحة كلها إلى use client بلا حاجة.
- أنواع بيانات العرض تفصل الاسم وslug والنسخ والصور وحالة الاعتماد. ProductCard لا يحسب ضريبة ولا يقرر حجزًا؛ Laravel مصدر التجارة عند الربط.
- مصدر fixtures منفصل خلف دوال صغيرة مثل listProducts/getProduct؛ لا تكرر أسماء/أسعار صلبة في كل مشهد. لا تبنِ SDK تجاريًا عامًا لهذه المعاينة.
- Route المعاينة موسوم noindex مع شارة مرئية «معاينة تصميم». noindex ليس وسيلة حماية؛ تظل المعاينة محلية ولا تنشر كمتجر.
- بعد اعتماد النموذج يستخدم مسار الإنتاج المكونات المشتركة مع بيانات API معتمدة، وتزال أو تعزل مسارات fixtures قبل الإطلاق. لا يعد نجاح المعاينة دليل نجاح الشراء.

## 10. القبول والتحقق

قبل GATE-VISUAL:

- [ ] /preview ورابط المنتج وCTA والتنقل الموجود تعمل؛ لا روابط توهم بصفحات غير منفذة.
- [ ] المنتج والشعار والعنوان والزر مقروءة في أول عرض؛ لا خلفية سودا فقط حتى تحميل JavaScript.
- [ ] صور 375 و390 و1440px محفوظة، وفحص 320px و768px دون قص/تمرير أفقي.
- [ ] صورتان للرئيسية وPDP في reduced-motion، وتسجيل 8-15 ثانية للحركة العادية.
- [ ] تعطيل JavaScript لا يخفي صورة Hero أو النص أو الرابط؛ التفاعلات المتقدمة يمكن أن تبقى غير متاحة في المعاينة.
- [ ] إعادة تحميل الصفحة والتنقل والعودة وتغيير عرض النافذة لا يضاعف الحركة أو listeners.
- [ ] لوحة المفاتيح وfocus وتسميات الأزرار تعمل، ولا يقع النص تحت طبقة زخرفية أو drawer مغلق.
- [ ] lint وtype-check وbuild حسب الأوامر الفعلية للتطبيق؛ النتيجة NOT RUN إذا تعذرت، مع السبب.

قبل تسليم CINE-06:

- [ ] مراجعة [UI_ACCEPTANCE_CRITERIA](UI_ACCEPTANCE_CRITERIA.md) في حدود الواجهة، وتسجيل معايير التجارة «لم تربط بعد»، لا PASS.
- [ ] قياس production build المحلي بثلاث جولات موثقة؛ جهاز وشبكة وأداة ووقت ووسيط النتائج. staging يعاد قياسه عند توفره.
- [ ] ميزانية Hero للهاتف ≤ 250KB كهدف المشروع المبدئي، وصورة واحدة فقط تعطى أولوية التحميل عند الحاجة؛ صور أسفل الطية مؤجلة ولها sizes وأبعاد.
- [ ] استهداف LCP ≤ 2.5s وCLS ≤ 0.1 تحت ظروف القياس المعلنة؛ لا تدّعِ INP ميدانيًا من Lighthouse. راجع [QUALITY_AND_RELEASE](QUALITY_AND_RELEASE.md).
- [ ] لا 3D أو فيديو تلقائي أو شحن مكتبة الحركة لكل الصفحات؛ المشهد المتوقف أو خارج الشاشة لا يستهلك حلقة رسم مستمرة.
- [ ] صور وأسماء ORQ المعلقة لا تتحول إلى نشر تلقائي؛ قائمة اعتماد D01/D03/D09 والنواقص موجودة.

يحفظ المنفذ الأدلة في evidence/frontend/cine-XX/، مثل home-390.png وproduct-1440.png وmotion-desktop.webm وتقرير التحقق. يسجل المتصفح والمقاس والجهاز الفعلي أو المحاكاة. لا يكفي كود مكتوب أو screenshot واحدة للحكم على الحركة والتجاوب.

## 11. نموذج تقرير جيميني

1. المهام المنفذة وأي اختلاف ضروري عن المواصفة.
2. الملفات والأصول المستخدمة، وهل البيانات أو الصور معتمدة أم مسودة.
3. أمر التشغيل ومسارات المعاينة وأوامر التحقق ونتائجها الفعلية.
4. روابط اللقطات والتسجيل والتقرير، والمقاسات والبيئة.
5. الاختبارات غير المنفذة والسبب؛ أخطاء console/الشبكة المتبقية.
6. ما ينتظر اعتمادًا بصريًا وما ينتظر بيانات أو API؛ لا تخلط بينهما.
7. حالة CINE الحالية والخطوة التالية؛ لا تقدم النموذج على أنه متجر بيع جاهز.

## 12. مراجع التنفيذ الرسمية

مواصفات المشاهد والأرقام أعلاه اختيارات لهذا المشروع. تحقق من API الفعلية وفق النسخ المثبتة:

- [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion): احترام تفضيل تقليل الحركة.
